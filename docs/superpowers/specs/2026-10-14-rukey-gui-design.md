# Rukey — GUI-приложение, фильтр слов и адаптивная отмена

Дата: 2026-10-14
Статус: на ревью
Точка отката: `2b498f7` (до всех изменений из этого документа)

---

## 1. Зачем

Сейчас Rukey — консольный демон. Его запускают через `swift run rukey`, он
печатает в терминал, а закрыть его можно только `Ctrl+C`. Три проблемы:

1. **Не видно, что он работает.** Нет интерфейса — пользователь не знает, запущен
   ли демон, какая раскладка активна, что он сделал.
2. **Настройки требуют правки JSON руками.** Исключённые приложения живут в
   `~/.config/rukey/exclude.json`, который надо редактировать вручную.
3. **Автозамена необратима.** Единственный способ отменить — тапнуть `⌥` в
   течение 1.2 секунды. Опоздал — и вместо отмены молча переключается раскладка.

Цель: полноценное приложение с меню-баром, окном настроек, пользовательским
фильтром слов и отменой, которая не протухает по таймеру.

## 2. Цели, не-цели, анти-цели

### Цели

- Приложение `.app`, запускаемое двойным кликом, без консоли
- Иконка в меню-баре как единственная точка входа
- Окно настроек: слова, приложения, общее, журнал
- Фильтр слов: пользователь задаёт слова, которые не заменяются
- Свой словарь: пользователь учит Rukey словам, которых нет в словаре
- Обучение: частые отмены автозамены сами превращаются в правило
- Отмена без таймера — пока курсор не мог уехать
- Встроенный просмотр журнала вместо `--verbose` в терминале
- Автозапуск при входе в систему, переключаемый из интерфейса

### Не-цели

- Не делаем облачную синхронизацию настроек
- Не делаем систему плагинов
- Не делаем обучение на ML
- Не делаем портретный режим (только меню-бар, без плавающей панели в углу)
- Не переписываем проект на другой язык (см. раздел 4)

### Анти-цели

Цель, при которой работа считается проваленной, даже если код компилируется:

- **Автозамена ломает то, что не должна.** Если фильтр или отмена начнут
  портить текст или раскладку — это провал, а не «известное ограничение».
- **Программа «работает», но пользователь об этом не знает.** Молчаливый сбой
  хуже явной ошибки. Всё, что происходит, должно быть видно в журнале.
- **Права Accessibility теряются после каждой пересборки без объяснения.**
  Пользователь должен понимать, что произошло и что делать.

## 3. Ограничения

| Ограничение | Источник |
|---|---|
| macOS 13.0+ | `Package.swift`, `.macOS(.v13)` |
| Swift 6.0+, strict concurrency | `swift-tools-version: 6.0` |
| Права Accessibility обязательны | `CGEventTap`, `AXIsProcessTrustedWithOptions` |
| `Unikod` (устаревший способ вставки) использовать нельзя | ломает ввод в сторонних приложениях |
| Клавиатура-буфер физически изнашивается | `KeyboardRemapping` для Toggle не рекомендуем, но `Press and Hold` — можно |
| Event tap живёт на главном run loop | `EventTapManager.start()`, `CFRunLoopAddSource(CFRunLoopGetMain(), …, .commonModes)` |

Последнее ограничение — ключевое. Оно означает, что tap переживёт переход на
`NSApplication`, потому что `NSApplication.run()` крутит тот же главный run loop
в `.commonModes`.

## 4. Решение по языку: остаёмся на Swift

Рассмотрено и отклонено. Фиксируем, чтобы не переигрывать.

| Аргумент за переход на Rust | Почему он не работает здесь |
|---|---|
| «Безопаснее» | Нет небезопасной работы с памятью: `Trie` — указатели на узлы под `NSLock`, строки иммутабельны |
| «Быстрее» | Prefix-check занимает ~1.2 мкс. Узкое место — доставка событий через mach-порты, не наш код |
| «Словари быстрее грузятся» | Разница на 1.1 МБ текста — десятки мс один раз при старте |
| «Нет GC-пауз» | Swift на macOS использует ARC без фонового GC; паузы отсутствуют |

Rust потребовал бы ручного FFI для `TISSelectInputSource`,
`keyboardSetUnicodeString`, `IsSecureEventInputEnabled` и определения активного
приложения — то есть переписать весь платформенный слой ради нулевого выигрыша
в производительности.

**Решение: Swift.** Это решение исполнителя, не согласованное отдельно.

## 5. Архитектура

Ноль IPC, ноль отдельных процессов. Демон и интерфейс — один процесс.

```
RukeyCore                       ← чистая логика, без AppKit-окон
  Detector ──────► WordFilter ──► ExclusionTrie
  RukeyUndoManager ──► StrikeStore
  RukeyConfig, DictionaryLoader, Trie, LayoutConverter, …
  LogBuffer                      ← кольцевой буфер журнала
  AppEventHub                    ← ObservableObject для UI

RukeyApp                        ← NSApplication
  AppDelegate                    ← жизненный цикл, таймеры
  StatusItemController           ← NSStatusItem + меню
  SettingsWindowController       ← окно настроек
  AboutWindowController

RukeyMeasure                    ← бенчмарк, не трогаем
```

Ключевой приём: ядро не знает про UI. `EventTapManager` уже публикует события
через колбэки `onCorrection`, `onOptionUndo`, `onOptionToggle`, `onOptionIgnored`.
`AppEventHub` подписан на них и раздаёт их SwiftUI. Ядро менять не нужно.

Побочный плюс: `swift run rukey-measure` продолжает работать без GUI.

## 6. Спецификация поведения

### 6.1 Фильтр слов

**Семантика: совпадение по вводу.** Запись `иуикф` означает «когда я набираю
`иуикф` в русской раскладке, оставь как есть». Слово `bebra`, набранное в
английской раскладке, фильтр не касается — его в списке нет.

**Почему именно так.** Вариант «блокировать результат» рассмотрен и отклонён:
он не позволяет выразить исходное намерение. Если в списке `привет`, а я
набираю `привет` в русской раскладке — он уже есть, и заменять нечего.

**Блокировка с начала набора.** Проверка выполняется на каждом шаге, а не
только на границе слова. Вариант «переключить раскладку на третьем символе,
а на границе слова вернуть обратно» отклонён: после переключения буфер уже
не содержит исходного набора.

Прослеживание на примере `иуикф` (физические клавиши `b`, `e`, `b`, `l`, `a`):

| Набор | Без фильтра | С фильтром |
|---|---|---|
| `иу` | проверки нет (< 3) | без проверки |
| `иуи` | `beb` — валидный префикс → **переключает на EN** | `иуи` — префикс слова `иуикф` → не переключает |
| `иуик` | `bebb` | не переключает |
| `иуикф` | `bebbl` | не переключает |
| пробел | `bebbl` остаётся мусором | `иуикф` остаётся ✓ |

**Механизм.** Слова исключений складываются в ещё один `Trie` — структура уже
есть в `RukeyCore/Trie.swift`, `insert(contentsOf:)` строит из набора за одну
блокировку, `hasPrefix` и `contains` приводят регистр сами.

- На лету (`Detector.evaluate`, `Detector.swift:98`): если
  `exclusionTrie.hasPrefix(буфер)` — не переключать раскладку
- На границе слова (`Detector.evaluateFullWord`, `Detector.swift:109`): если
  `exclusionTrie.contains(слово)` — не заменять
- С запятыми и прочими знаками (`decisionForPunctuatedToken`,
  `Detector.swift:131`): та же проверка по `originalText`

**Известное ограничение — протекание на один символ.** Если в списке `asdf`,
набор `asdf` заблокирован, а `asdfx` — уже нет. На практике безвредно: `asdfx`
в русскую раскладку даёт `фывфщ`, что не слово, и переключения не будет.
Документируется, не чинится.

**Горячая перезагрузка.** Список меняется в окне настроек → `WordFilter`
перестраивает `Trie` и подменяет его атомарно. Перезапуск программы не нужен.

### 6.2 Адаптивная отмена

**Проблема, которую решаем.** Окно 1.2 с — не единственный ограничитель. Отмена
сбрасывается ещё и от любого нового символа, от `⌫`, от `⌘`/`⌃`, от стрелок,
`Tab`, `Enter`, от смены приложения, от защищённого ввода. Когда отмены нет,
`⌥` не «не делает ничего», а **переключает раскладку** — это хуже, чем
молчание, потому что меняет состояние, о котором пользователь не просил.

**Решение: убрать таймер как жёсткий запрет.**

- **Символы, набранные после автозамены, не сбрасывают отмену — они
  дописываются в хвост.** Механизм `appendedTail` уже существует в
  `LastCorrectionState` (`UndoManager.swift:9`), сейчас используется только для
  пробела. Отмена съест и их, и вернёт исходное слово.
- **Сбрасывается только то, что может означать уход курсора:** стрелки, `Tab`,
  `Enter`, `Escape`, смена активного приложения, защищённый ввод, `⌘`/`⌃`.
- **Клапан безопасности:** если после автозамены набрано больше 64 символов,
  отмена сбрасывается. Защита от каскадного стирания при сбое.

**Клавиша `⌥` не меняет смысл.** По решению владельца переключение раскладки
остаётся на `⌥`. Приоритет сохраняется: если есть что отменять — отменяет,
иначе переключает раскладку. С новой отменой, переживающей набор, приоритет
становится предсказуемым.

**Побочная правка.** `⌥` при включённом Secure Input больше не переключает
раскладку. Сейчас код в `EventTapManager.handleFlagsChanged` этого не проверяет,
хотя `SecureInputMonitor.shouldBypassForActiveApplication()` даёт запрет на
автозамену. Это баг: в полях ввода паролей тап `⌥` меняет раскладку. Добавить
ту же проверку.

### 6.3 Обучение

**Правило: считаем отмены, не срабатывания.** Отмена одного и того же слова три
раза → слово попадает в фильтр. Считать все срабатывания нельзя: тогда в
исключения попадут слова, которые пользователь на самом деле хочет заменять
(`привет` → `hello`).

**Порог настраиваемый:** 2 / 3 / 5 / выключено. По умолчанию 3.

**Уведомления:**

| Событие | Уведомление |
|---|---|
| 1-я отмена слова (порог не достигнут) | Да, если включён «тихий режим выключен» |
| 2-я отмена слова | Да, если тихий режим выключен |
| Слово добавлено в исключения | Да, всегда. Огонёк на иконке + строка в меню |
| Срабатывание фильтра | Нет — пользователь этого ждал |

**Тихий режим.** Настройка «уведомлять о каждом отменённом слове», по умолчанию
**выключена**. При пороге ≤ 3 интерфейс сам предлагает её включить.

Обоснование: по умолчанию включённые уведомления при пороге 3 перестанут
приходить к 4-му отмене того же слова, и через неделю пользователь их выключит.
Порог выше 3 делает трюк с уведомлениями бессмысленным — поэтому настройка
существует вместе с тихим режимом, а не вместо него.

**Обучение одностороннее.** Попав в фильтр, слово больше не заменяется никогда.
В окне слов такие слова показываются явно, с кнопкой удаления.

### 6.4 Свой словарь

Слова, которых нет в словаре, учат автозамене. Хранятся отдельно от фильтра и
не влияют на него. Обе таблицы живут на одной вкладке «Слова»: сверху «Не
заменять», ниже «Мои слова».

### 6.5 Исключения приложений

Поведение не меняется — `excludedBundleIDs` и `excludeTerminals` уже работают.
Меняется только ввод: вместо правки JSON — окно со списком установленных
приложений и поиском по названию. Сканируются `/Applications`,
`/System/Applications`, `~/Applications`. Значение берётся из bundle ID.

По умолчанию — работа во всех приложениях, кроме явно исключённых.

## 7. Схема хранения

Три файла в `~/.config/rukey/`. Текущий `exclude.json` расширяется, формат
не ломается.

### `exclude.json`

```json
{
  "excludeBundleIDs": ["com.apple.Terminal"],
  "excludedWords": ["иуикф", "ghbdtn"],
  "launchAtLogin": false,
  "autoLearnThreshold": 3,
  "quietModeOnLearn": true,
  "showCorrectionFlash": true,
  "minPrefixLength": 3
}
```

Текущий парсер (`RukeyConfig.swift:49`) молча игнорирует отсутствующий или
битый файл. Поведение сохраняем, но теперь пишем причину в журнал — иначе
опечатка в JSON выглядит как «настройки не применились».

### `learned.json`

```json
{ "strikes": { "ghbdtn": 2 } }
```

Отдельный файл, чтобы `exclude.json` оставался чистым. В temp-файл счётчики
не кладутся намеренно: `/tmp` и `/var/folders` macOS чистит сам, в том числе
при перезагрузке, а смысл обучения — в накоплении.

### `custom.json`

```json
{ "words": ["абракадабра", "жуль"] }
```

## 8. Интерфейс

### 8.1 Меню-бар

Иконка в правом верхнем углу. Док, панель в углу экрана, отдельное окно при
запуске — не используются. `LSUIElement = true` в `Info.plist`.

**Иконка:** собственная векторная молния, обводка и заливка как у клавиш.
Рисуется чёрным с альфой и помечается как template image — macOS сам
инвертирует под светлую и тёмную панель. Поэтому «белая молния, меняющаяся
под тему» — это одна чёрная молния с прозрачностью, а не два файла и не код
слежения за темой. Размер 18×18 pt, @1x и @2x. Плюс цветная версия для окна
приложения.

Иконка выбрана потому, что ⚡ уже в бренде: `# Rukey ⚡` в README и
`⚡ [Auto-Correct]` в журнале.

**Пункты меню:**

| Пункт | Поведение |
|---|---|
| Статус | «Работает» / «Нет прав Accessibility» / «Приостановлено: защищённый ввод» |
| Текущая раскладка | `RU` / `EN` |
| Последняя автозамена | `ghbdtn → привет` |
| Автозапуск при входе | чекбокс |
| Настройки… | окно |
| Журнал… | окно на вкладку журнала |
| Выйти | `NSApp.terminate` + `tapManager.stop()` |

При автодобавлении слова в исключения — иконка коротко мигает и появляется
строка «Запомнено: ghbdtn» с возможностью отменить прямо из меню.

### 8.2 Окно настроек

SwiftUI в `NSWindow` через `NSHostingView`, четыре вкладки.

**Слова** — две секции. «Не заменять»: поле ввода (Enter добавляет), список с
удалением, «Очистить всё». «Мои слова»: то же самое.

**Приложения** — кнопка «Добавить приложение» → окно со списком установленных
приложений и поиском. Список текущих исключений с удалением.

**Общее** — минимальная длина префикса, исключать терминалы, автозапуск,
порог автообучения, тихий режим, всплывашка после автозамены. Кнопка «Открыть
настройки Accessibility».

**Журнал** — последние записи с переключателем «только ошибки». Приложение
запущено двойным кликом, `--verbose` в терминале недоступен, поэтому
внутренний просмотр журнала — обязательная часть, а не украшение.

### 8.3 Уведомления

- **Уведомления системы** (`UNUserNotificationCenter`, требует разрешения) — для
  отмен и автодобавления слов
- **Всплывашка после автозамены** — маленькое окно 220×54 в правом верхнем углу,
  1.5 секунды, переключаемое. Показывает `ghbdtn → привет`. Нужна, чтобы не
  искать автозамену в меню

### 8.4 Права Accessibility

Сейчас при отсутствии прав программа печатает текст и делает `exit(1)`
(`main.swift:64-68`). Это тупик для приложения, запущенного двойным кликом.

Правильное поведение: красный статус в меню, кнопка «Открыть настройки
Accessibility» прямо в System Settings, демон ждёт разрешения и продолжает
работу, а не выходит.

Пересборка `.app` в новом месте сбрасывает разрешение, потому что права
привязаны к пути бинарника. Это нужно проговаривать при установке.

## 9. Процесс разработки

Требования владельца: работа с навыками, субагенты и проверка кода с
немедленным исправлением найденного.

### 9.1 Навыки

| Навык | Когда |
|---|---|
| `test-driven-development` | Каждая новая функция. Тест падает → пишем код → тест зелёный |
| `systematic-debugging` | Любой сбой. Не гадать, а воспроизвести и найти причину |
| `verification-before-completion` | Перед словом «готово». Только после запуска команды |
| `requesting-code-review` | После каждой фазы, до коммита |
| `receiving-code-review` | При получении замечаний: проверить технически, а не согласиться сразу |

### 9.2 Субагенты

Независимые части запускаются параллельно, когда не делят состояние.

Кандидаты на параллельную работу:

- Иконка (вектор + template-вариант + цветная) — не зависит от кода логики
- Пикер приложений (сканирование + поиск) — отдельный модуль
- Окно настроек, вкладка «Общее» — зависит только от конфига
- Тесты `Trie` / `LayoutConverter` — независимы от движка

Не параллелизировать: правки в `Detector` и в `EventTapManager` идут в одном
потоке, потому что оба в горячем пути и связаны отступами.

### 9.3 Проверка кода и починка

После каждой фазы:

1. Прогнать тесты и `swift build`
2. Субагент-ревьюер смотрит диф свежему взглядом
3. Найденное сразу чинится через `systematic-debugging` — без паузы на
   согласование, если это очевидный баг
4. Находки, меняющие поведение, — выносятся владельцу до починки
5. Повторная проверка: тесты зелёные и ревью закрыто
6. Коммит + `git push`

Ревью не может остаться незакрытым: фаза не считается законченной, пока
замечания либо исправлены, либо явно отклонены с обоснованием.

### 9.4 Фазы

Порядок выбран так, чтобы каждая фаза оставалась работоспособной.

| № | Фаза | Тест критерий |

## 10. Решения исполнителя

Эти вопросы не задавались владельцу, решены самостоятельно и могут быть
пересмотрены:

- **Словарь исключений — отдельный `Trie`**, а не проверка по `Set`. Причина:
  `Trie` уже даёт `hasPrefix` и `contains` с приведением регистра, а проверка
  «является ли набранное префиксом слова из списка» на `Set` потребовала бы
  линейного перебора
- **`WordFilter` владеет своим `Trie` и подменяет его целиком** при изменении
  списка. `Detector` получает ссылку на `WordFilter`, а не на `Trie`, чтобы
  менять список без пересоздания `Detector`
- **`learned.json` вместо temp-файла** — см. раздел 7
- **Счётчик учитывает отмены, не срабатывания** — см. раздел 6.3
- **Всплывашка после автозамены добавлена как переключаемая** — не запрашивалась,
  но решает проблему «куда смотреть»
- **История последних автозамен в окне** с кнопкой «отменить эту» — отложенная
  владельцем идея, возвращена в упрощённом виде как почти бесплатная
