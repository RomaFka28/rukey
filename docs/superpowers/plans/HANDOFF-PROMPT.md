## Контекст

Rukey — демон для macOS, который исправляет опечатки в раскладке на лету:
печатаешь `ghbdtn` → получаешь `привет`, печатаешь `реддщ` → `hello`.
Работает через `CGEventTap` на главном run loop.

Проект: `/Users/roman/Desktop/рукей` (путь содержит кириллицу, квотируй его в командах).

повторных вопросов и не открывай фазу брейншторминга.** Твоя работа — выполнить
планы.

## Жёсткие ограничения

Из спеки, нарушать нельзя:

- `RukeyCore` остаётся без UI. Никаких `import AppKit`/`SwiftUI` в ядре. Ядро
  меняется только узкими сеттерами под `NSLock`
- Консольный `rukey` сохраняет все флаги. После каждой задачи:
  `swift run rukey --test-conversion` должен давать те же пять строк
- Нигде в GUI-таргете нет `exit(1)`. Без прав Accessibility приложение живёт,
  показывает красный статус и ждёт
- Не заменять вставку через Unicode API в `FixEngine` на `Unikod`
- Словари грузятся один раз. Всё добавленное в путь решений `Detector` должно
  быть O(длины префикса), без линейных переборов
- Счётчик слов ~1.2 мкс на нажатие. Не добавляй в горячий путь ничего, что
  ломает это

## Правила отчётности

**Не выдумывай результаты.** Если задачу нельзя проверить — так и напиши.

Конкретно: в планах есть ручные проверки, помеченные `Manual check`. Они требуют
реального выданного доступа Accessibility и живой клавиатуры. Если ты их
выполнить не можешь:

- выполни всё автоматизируемое
- перечисли в отчёте каждую непроверенную позицию списка из шага
  «Manual check» или из финальной таблицы Task 8
- **не** помечай их выполненными

То же самое с `--check-permissions`, визуальной проверкой иконки и меню.

Перед словом «готово» запусти команду и покажи её вывод. «Должно работать» —
это не результат.
